# 展覧会の保存・削除仕様（検討用）

作成日：2026-10-02

## この文書の位置づけ

登録・編集・共有取り込み・削除と、それに伴う期限通知を対象とする。
「現状」はコードを読んで確認した動作であり、製品仕様として承認済みという意味ではない。画面操作、OSの通知配送、実際のディスク障害は今回検証していない。
「提案」は今後決める仕様の候補。決定前に、現状の不統一をそのまま正解としてテストに固定しない。
この文書作成ではアプリの実装を変更せず、テストも追加しない。

## 1. 現在の動作

### 登録

- 展覧会名の前後の空白・改行を除いた結果が空、または会場が空文字の場合、保存ボタンを無効にする。
- 会場の空白だけの入力は、この判定では拒否されない。名前と会場は入力した文字列のまま保存する。住所は前後の空白・改行を除く。
- 開始日と終了日は日付選択で入力する。終了日が開始日より前でも、登録時の保存処理では補正・拒否をしていない。
- 新しいIDで展覧会を作り、明示的な保存に成功してから期限通知の更新処理を待ち、画面を閉じる。
- 保存前に「閉じる」を押すと登録しない。入力破棄の確認や下書き保存はない。

### 編集

- 既存データを編集用の入力状態へコピーする。保存時に元の展覧会へ反映し、同じIDで更新する。
- 保存ボタンには登録画面と同じ必須項目チェックがなく、空の名前・会場も保存できる。
- 名前・会場・住所は前後の空白・改行を除く。
- 終了日が開始日より前なら、終了日を開始日と同じ値へ変更して保存する。この補正は入力状態にも反映される。
- 保存成功後に期限通知の更新処理を待ち、画面を閉じる。
- 保存前にキャンセルすれば入力を破棄し、元の展覧会へ反映しない。破棄確認はない。
- 編集状態への読み込み時に、特別開館日のルールは単日だけへ絞られる。期間ルールが保存されていた場合、変更せず保存しても失われる可能性がある。

### 共有からの取り込み

- 毎回、新しいIDで登録する。取り込み済みかどうかを判定する処理はない。
- 名前・会場の必須チェックはない。
- 開始日を解釈できなければ現在日時を使う。終了日を解釈できなければ開始日を使う。終了日が開始日より前なら開始日と同じ値を使う。
- ポスターの取得中・取得失敗でも登録できる。登録時点で取得できている画像だけを保存し、後から取得した画像を登録済みデータへ追記する処理はない。
- 保存と期限通知の更新処理を経て画面を閉じ、取り込み完了の処理を呼ぶ。保存失敗時は閉じず、完了処理も呼ばない。

### 共通の保存処理と失敗時

- 同じ画面で処理中に再度実行を要求しても、重複して開始しない。
- 共通の画面処理は、処理中表示、操作の無効化、スワイプによる画面終了の禁止、戻るボタンの非表示を指定している。各画面で実際に防げる操作範囲はUIテストで確認が必要。
- 保存が失敗すると画面を残し、エラーメッセージを表示する。入力状態を保持して再試行できる。ただし、保存前に行った日付などの補正までは元に戻していない。
- 今回の変更を取り消すため、SwiftDataのロールバックを行う。編集では保存前の値も控えて復元する。
- 同じ保存コンテキストに以前から未保存の変更がある場合、今回の操作より先にそれを保存する。その事前保存が失敗した場合は今回の変更を開始しない。事前保存できた変更は今回の失敗で取り消さない。
- 登録・編集の保存失敗時に、期限通知の更新は開始しない。

### 削除

- 詳細画面で削除確認を出す。キャンセル時は変更しない。
- 展覧会の削除を保存できた後、そのIDの期限通知（7日前・1日前）を予約済み・配信済みの両方から除去し、画面を閉じる。
- 削除の保存失敗時はロールバックし、通知解除を行わずエラーを表示する。
- ポスターのサムネイルとメモは展覧会の保存データに含まれる。別ファイルの画像、共有先のクラウドデータ、外部カレンダーの予定を削除する処理はない。
- `Reminder`モデルは展覧会IDを文字列として持つが、連動削除の実装はない。近隣通知も展覧会ID単位で解除する構成ではない。

### 期限通知

- 登録・編集・取り込みの保存後に、既存の予約を外して予約し直す。設定がOFFなら外すだけ。
- 終了日の7日前と1日前を対象に、設定された時刻で通知を予約する。訪問済みかどうかによる除外はない。
- 過去かどうかの判定は「終了日時から7日／1日引いた日時」で行い、その後に通知時刻を合成している。このため「本日の9時がまだ未来か」といった境界で予約判定がずれる可能性がある。
- 日時計算には端末の現在のカレンダーを使う。
- 通知追加のエラーは無視される。通知予約に失敗してもデータの保存は成功扱いで、画面を閉じる。
- 設定画面は初期表示としてON・9:00を使う。一方、保存処理は設定キーが未保存の場合、ON/OFFを直接読み取るためOFF相当になる。未設定時の初期値を統一する必要がある。
- 設定変更時は全展覧会の期限通知を再設定する。OSの通知許可要求はホーム画面の処理で行う。

### 任意項目と今回の共通処理に含まれない更新

- URLは前後の空白を除き、HTTP(S)のURLとして解釈するか、先頭に `https://` を付けて再解釈する。変換できなければ未設定として扱い、保存エラーは出さない。入力文字列の厳密な妥当性を保証するものではない。
- 作品総数は整数に変換できなければ未設定になる。負数を拒否する処理はない。
- 一覧・詳細の訪問済み切り替えはモデルを直接変更する。メモも内容変更時にモデルへ反映する。今回の共通保存処理を通らず、明示的な保存失敗の表示がない。

## 2. 決めたい仕様と提案

すべて未決定。まずD1〜D4を決めると保存の主要なテストを書き始められる。

| ID | 決めること | 提案 |
|---|---|---|
| D1 | 必須項目・空白の扱い | 登録・編集・取り込みで統一。名前と会場は前後の空白を除いて保存し、空なら理由を示して保存しない |
| D2 | 終了日が開始日より前の場合 | 勝手に補正せず、入力を残して修正を促す。同日開催は許可。取り込みの日付が不正なら今日へ置換せず知らせる |
| D3 | 保存失敗・再試行 | 入力を保持し、保存済みの展覧会と通知を変えない。成功扱いにせず、再試行で二重登録しない。他の展覧会の変更を失わない |
| D4 | 通知予約だけが失敗した場合 | 展覧会の保存は維持し、「保存済みだが通知を設定できなかった」と区別して伝える。通知権限がない場合も保存自体は許可する |
| D5 | キャンセル・処理中の操作 | 通常のキャンセルは入力を破棄。変更があれば破棄確認を出す。保存中は連打と画面終了を防ぎ、終了後に操作可能へ戻す |
| D6 | 削除に含める範囲 | 端末内の展覧会・そのメモと画像・期限通知を対象にする。共有済みデータと外部カレンダー予定の扱いは別途明示する |
| D7 | 共有の重複取り込み・画像待ち | 同じ共有元からの再登録には確認を出す。画像取得中は登録を待ち、取得失敗時は画像なしで登録できる選択肢を出す |
| D8 | 通知の初期値・対象日・時刻 | 未設定時の初期値を一か所で定義。時刻を合成した後の日時で過去判定し、過ぎた通知は送らない。0:00も有効な設定値とする |
| D9 | 日付の基準・訪問済み通知 | 会期を日本時間の日付として扱うか、端末の時間帯に従うかを決める。訪問済みの期限通知を続けるかも決める |
| D10 | 無変更保存による情報の欠落 | 入力していない項目も含め、何も変更しない保存で元データが失われないことを保証する |
| D11 | 任意項目の不正値 | 空欄は許可。入力があるのにURLとして扱えない、件数が負数などの場合は消して保存せず修正を促す |
| D12 | 訪問済み・メモの保存 | 明示保存とは別の自動保存仕様として、保存タイミング・失敗時の通知・再試行方法を整理する |

D7の「同じ共有元」の識別方法や、D6の画像・通知の所有関係は、仕様を決めた後に実装方法を検討する。

## 3. 仕様決定後のテスト候補

以下は期待する動作の候補。まだ合意済みの受け入れ条件ではない。

| ID | 条件・操作 | 期待する結果 | 関連仕様 |
|---|---|---|---|
| T01 | 有効な入力で登録 | 1件だけ保存され、成功後に画面を閉じる | D1・D3 |
| T02 | 名前・会場が空／空白のみ | どの登録経路でも保存せず、理由を示す | D1 |
| T03 | 終了日＜開始日／同日開催 | 前者は修正を促し、後者は保存できる | D2 |
| T04 | 編集してキャンセル | 元データと通知は変わらない | D5 |
| T05 | 登録の保存に失敗し再試行 | 入力を保持し、失敗時は登録・通知が残らず、再試行成功で1件になる | D3 |
| T06 | 編集の保存に失敗 | 元の保存値を維持し、入力は再試行用に残る。他のデータも失われない | D3 |
| T07 | 削除確認でキャンセル／削除保存失敗 | 展覧会も通知も残る | D3・D6 |
| T08 | 削除成功 | 対象の展覧会と定めた関連データ・通知だけを消す | D6 |
| T09 | 保存成功後に通知予約が失敗 | 保存は維持し、通知だけが失敗したことを伝える | D4 |
| T10 | 保存中に連打・画面終了を試す | 重複処理をせず、決めた範囲の操作を防ぐ | D5 |
| T11 | 画像未取得・不正日付・同じ共有の再取り込み | 決めた待機・エラー・重複確認の動作になる | D2・D7 |
| T12 | 通知OFF・設定未保存・0:00・通知時刻の前後 | 初期値と境界条件を含め、決めた通知だけを予約する | D8・D9 |
| T13 | 期間ルールを含むデータを無変更で保存 | 元の項目を欠落させない | D10 |
| T14 | 任意項目が空／不正 | 空は許可し、不正入力は指定した理由で拒否する | D11 |

保存処理や入力検証はSwift Testing、実際のボタン操作・画面遷移はUIテストで扱う。保存エラーと通知エラーを別々に再現できるようにし、通知は実際には送らない。テストごとに独立したデータを使う。
